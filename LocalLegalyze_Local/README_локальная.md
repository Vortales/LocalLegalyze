# LocalLegalyze — локальная версия (без сервера)

> Из серверной версии `TestLegalUniversal_v25` убрано всё, что ходило в сеть,
> и оставлено только то, без чего программа не работает: окно, встроенный чат,
> автовложение промта и шаблона, микрофон, горячие клавиши.
> Заодно исправлен дефект «в чат приезжают лишние PDF и Шаблон.txt».

---

## 1. Что внутри

```
LocalLegalyze_Local/
├── LocalLegalyze_Local.py     ← ВСЯ программа: один файл, 4700 строк, 21 раздел
```

## 2. Запуск

```bat
pip install -r requirements-local.txt
python LocalLegalyze_Local.py
```

Первый запуск — три коротких шага:

1. **«Шаблон»** — вписать имя, ID, фракцию, ранг, отдел, должность.
2. **Горячие клавиши** — нажать по полю и нажать нужную клавишу
   («Микрофон» — голос, «Окно» — свернуть/развернуть).
3. **«Промт»** — выбрать файл из папки `prompts/`
   (если папка пуста, программа положит туда пример и откроет её).

Дальше всё автоматически: программа запускает Chrome, открывает чат,
вкладывает в него `Промт.pdf` и `Шаблон.txt` и ждёт запроса.

**Нужен установленный Google Chrome** (или Edge/Chromium). Chrome — потому что
только в нём работает **штатный микрофон страницы**; в Edge/Chromium программа
работает, но голосовой ввод может быть недоступен — об этом будет надпись
в строке состояния.

## 3. Кнопки и что они делают

| Кнопка | Действие |
|---|---|
| **Шаблон** | Окно с шестью полями. Сохранение сразу перекладывает `Шаблон.txt` в чат заново |
| **Промт** | Список файлов из папки `prompts/`. Кнопка «Папка» открывает её в проводнике |
| **⟳** | Закрыть браузер и открыть заново, файлы вкладываются с нуля. Помогает, если страница «зависла» или просит войти |
| **✕** | Выход с корректной остановкой браузера |
| **Микрофон** (плашка) | Сменить горячую клавишу записи голоса |
| **Окно** (плашка) | Сменить горячую клавишу показа/скрытия |
| Перетаскивание | Окно тянется мышью за любую свободную область |

Нижняя строка: какие файлы сейчас должны быть в чате, выбранный промт,
индикатор готовности (`●` зелёный — файлы в чате, жёлтый — идёт вложение,
красный — нужен перезапуск).

## 4. Чего больше нет (и почему)

| Убрано | Почему |
|---|---|
| Окно авторизации, логин/пароль, токен | работает локально, аккаунта Legalyze нет |

| Диагностика `diagnostics.py`, `browser_trace.py` | вместо них один текстовый лог |

**Всего убрано 11 сетевых вызовов** (список — в `../TestLegalUniversal_v25/НАВИГАЦИЯ.md` §4).
Проверяется тестом: в коде нет ни `legalyzeai.ru`, ни `/api/client/`, ни `requests`.

## 5. Исправленный дефект: дубли файлов в чате

**Симптом.** `Окно чата → Memphis.pdf Шаблон.txt Memphis.pdf Шаблон.txt`,
и чем больше запросов сделано, тем чаще.

**Причина (разбор — `../TestLegalUniversal_v25/НАВИГАЦИЯ.md` §6).**
В серверной версии поток вложения решал «файла нет» по **одному** замеру сразу
после впрыска. Чип файла появляется в чате через 0.5–3 секунды, поэтому поток
успевал впрыснуть тот же файл ещё раз. Дедупликация была, но срабатывала только
при `present > 4` и **один раз за жизнь потока**, поэтому дальше дубли не лечились.

**Что сделано** (`plan_attachments()` — одна чистая функция, 60 строк):

| Правило | Было | Стало |
|---|---|---|
| Механизм впрыска | `input` **и** `drop` сразу | один: `input`, `drop` только если поля файла нет |
| Пауза после впрыска | 0.3 с и сразу новый замер | 1.6 с — страница успевает создать чип |
| «Пусто в чате» | по одному замеру | по двум подряд |
| Критерий готовности | два разных (`names_ok` / нет) | один: точное сопоставление «файл ↔ чип» |
| Безымянный чип | считался «файлов нет» → впрыск заново | считается «возможно, уже этот файл» |
| Дубликаты | лечение при `> 4`, один раз | удаление по одному, с проверкой после каждого |
| Сравнение имён | подстрока в обе стороны | точное → стем → подстрока (с нормализацией) |
| После подтверждения | поток продолжал проверять | «запор»: впрысков нет, пока файл не исчезнет |

**Проверено симуляцией** (`tests_local.py`), задержка появления чипа 0.3–4 с:

```
задержка 0.3 с: впрысков ровно 2, в чате ровно 2 файла
задержка 1.2 с: впрысков ровно 2, в чате ровно 2 файла
задержка 2.5 с: впрысков ровно 2, в чате ровно 2 файла
задержка 4.0 с: впрысков ровно 2, в чате ровно 2 файла
старое правило при 4.0 с: 20 впрысков вместо 2  ← причина дефекта
```

### 5.1. Смена шаблона или промта больше не оставляет старый файл

Имя файла шаблона всегда одно и то же — `Шаблон.txt`. Раньше, если файлы уже
лежали в чате, правило вложения считало их «уже вложенными» и новый текст
шаблона просто не доезжал до модели: отправлялся старый. Теперь при повторной
подготовке программа сначала **снимает** прежние чипы и только потом вкладывает
новые — файл в чате всегда соответствует тому, что показано в окне программы.

## 6. Исправленные «подлагивания»

Ощущение «окно начинает подлагивать после нескольких запросов» давала не
нагрузка браузера, а сам клиент:

| Что грузило | Было | Стало |
|---|---|---|
| Логи | `diagnostic.jsonl` + `events.log` синхронно, из нескольких потоков | буфер в памяти, сброс раз в 2 с, один файл с ротацией |
| Каждые 5 с | добавочный `eval` страницы (`log_page_probe`) | нет |
| Каждый впрыск | чтение файла + SHA-256 (PDF на МБ) + `eval` аудита | нет |
| «Вложение не работает» | выгрузка **всего HTML** страницы на диск | одна строка в логе |
| Пересылка PDF | одно CDP-сообщение ~4 МБ | кусками по 1.2 МБ, и **повторно не пересылается** |
| Дерево процессов | снимок Toolhelp32 на каждый процесс | один снимок на вызов, `taskkill /T` |
| Опрос чата | 20 раз в секунду в любом случае | 2.5 раза в секунду, после подтверждения — 1 раз |

## 7. Linux / macOS

Программа рассчитана на Windows (Win32-вживление окна, `GetAsyncKeyState`,
профиль Chrome). На других системах запускается только для разработки:
браузер откроется отдельным окном, горячие клавиши и вживление недоступны.

## 8. Если что-то не так

| Симптом | Что делать |
|---|---|
| «Нужен Google Chrome» | установить Chrome, нажать «⟳» |
| «Войдите в Google, затем ⟳» | в открытом окне войти в аккаунт, нажать «⟳» |
| «Файлы не вложились» | нажать «⟳». Если повторяется — открыть `prompts/` и убедиться, что промт открывается |
| Файл в чате не тот | имя PDF = имя файла промта. Переименуйте файл в `prompts/` |
| Промт `.txt` не собирается | `pip install fpdf2` (либо положите промт готовым PDF) |
| Дубли всё-таки появились | пришлите `logs/locallegalyze.log` — там видно каждый впрыск и причину решения |
| Голосовой ввод не работает | проверьте разрешение микрофона в Windows и что запущен именно Chrome |

Лог: `logs/locallegalyze.log` (ротация при 2 МБ, хранится один предыдущий файл).
